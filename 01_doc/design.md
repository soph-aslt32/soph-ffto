## 合成データ生成器の仕様

> 状態：実装済み（`02_src/ftto_sim/`）．ただし「実装時に置いた仮定」は未確認．

### 目的

- ログX・A・B・Cと同じ形式の合成ログを生成する
- 同時に，真値（各Posの処理時間，ロボットの占有時間，各部位の稼働率など）を出力し，推定結果と照合できるようにする

### 装置モデル（確認済みの事項に基づく）

- 装置は Unit の列．各 Unit は Pos を持つ
- Pos の種類：処理層／コンベア／ロボットハンド
  - 種類は拡張できるようにする
- 各 Pos の容量は1枚
- ロボットは Upper/Lower の2ハンドを持ち，各ハンドは1つの Pos として扱う
  - 2ハンドは同時に動けない（ロボット本体が1つの資源）
  - 入れ替え動作あり
- 並列の処理層：インデックスが若い順に，空いている層へ投入する
- 投入：カセット単位で設置し，外部から指定された間隔で1枚ずつ取り込む

### 入れ替え動作（確認済み）

例：Pos1（コンベア）→ Pos2（処理層）→ Pos3 の場合の基本手順

1. Upperハンドが Pos1 から新しいマテリアルを取る
2. ロボットが Pos2 へ移動する
3. Lowerハンドが Pos2 から処理済みのマテリアルを取る
4. Upperハンドが新しいマテリアルを Pos2 に置く
5. ロボットが Pos3 へ移動し，Lowerハンドのマテリアルを置く

- ルールは装置構成で変わるため，差し替え可能な実装にする
- 処理済みマテリアルがまだ無い場合，入れ替えは成り立たない
  - 例：Upperハンドで置いたあと，すぐに上流から新しいマテリアルを取る動作に移る

### その他の確認済み事項

- ログAの投入時刻は実際の取り込み時刻．能力を超えて取り込むと装置内が混雑し，先頭の取り込みも待たされる
- 処理IDは基本的にカセット単位で同じ．マテリアルごとに付けることも可能
- 処理層の処理時間はほぼ一定．ただしロボットとの兼ね合いで処理層内に滞留するため，滞在時間は変化する
  - 生成器では，純粋な処理時間（真値）と，滞在時間（ログ上の IN〜OUT）を区別して出力する
- ログCの行の Pos はハンドの Pos
- ログ形式：本ワークスペースで標準形式を定義し，実ログはユーザー側で変換する．乖離が大きければ標準形式を見直す
- 生成器は Python，重い推定処理は Rust

### シミュレーション方式

- 離散事象シミュレーション
- 時刻は内部では実数で扱い，ログ出力時に秒単位へ丸める

### 設定項目（案）

設定ファイル（TOML を提案）で次を指定する．

- 装置構成：Unit・Pos の列，Pos の種類，ロボットとハンドの対応，搬送経路（どの区間をどのハンドが担うか）
- 処理時間：（処理層 Pos, 処理ID）ごとの処理時間と，そのばらつき
- ロボット動作時間：移動時間，取る時間，置く時間
- 投入：カセットあたりの枚数，取り込み間隔，処理IDの出現比率
- 打刻ラグ：上流OUT〜下流INのラグの分布
- ログCの欠落：行き先・動作内容が欠ける割合
- 期間，乱数シード

### 出力

- ログX・A・B・C（CSV を提案）
- 真値ファイル

### ログCの拡張性

- 動作開始・終了を出力する Pos の種類を設定で切り替えられるようにする（当面はロボットのみ）

### ロボット作業の優先順位（仮）

- 正式なルールはユーザー側で情報収集中
- 確定までは「上流優先」を仮ルールとする（ユーザー指示）
  - 実行可能な作業のうち，搬送元の段がより上流のものを先に行う
- 差し替え可能な実装にする

### 並列の処理層での入れ替え（確認済み）

- 処理済みマテリアルが残っている層も，入れ替え動作の対象（「空いている層」と同様に扱う）
- 層の選択は，空いている層または入れ替え可能な層のうち，インデックスが若いもの

### 実装時に置いた仮定（未確認・要確認）

1. （確認済み）取り込み間隔は，実際の取り込み時刻から指定間隔を空ける
2. カセット間の追加の空き時間：既定 0 秒（設定で変更可）
3. 同じ段に処理済みマテリアルが複数あるとき，ロボットは先に処理が終わったものから取る
4. 上流優先の結果，下流が埋まっていても，ロボットは上流のマテリアルを先に取って保持する
5. 入れ替え動作の途中（手順5）で下流が埋まっていれば，ロボットは他の作業をせずにその場で待つ
6. ログCの動作の粒度：MOVE・PICK・PLACE を別々の動作として出力する
   - MOVE は，次に取る・置くハンドの Pos に記録する
   - 欠落は，動作内容と行き先の両方を空欄にする
7. 打刻ラグ：上流OUT は実時刻，下流IN は実時刻に一様分布のラグを足した時刻で打刻し，秒単位に切り捨てる
8. コンベアは「搬送時間が一定の Pos」として扱う．コンベア間など，ロボットを介さない受け渡し（`feed = "auto"`）も可能
9. 先頭段（load）にはマテリアルが直接現れ，最終段（unload）からは処理完了後に自動で払い出される
10. 処理層の処理は，マテリアルが置かれた（IN）時点で即座に始まる
11. ロボットは段ごとに位置を持ち，段間の移動に時間がかかる（既定値と区間ごとの上書き）
12. ログXの列：`seq, unit_id, pos_id, pos_kind, robot_id, hand`．設定ファイルの Unit・Pos の記述順を上流からの順とする

### 実装の構成

| ファイル | 役割 |
|---|---|
| `ftto_sim/config.py` | TOML 設定の読み込みと検証 |
| `ftto_sim/topology.py` | Pos・段・ロボット・マテリアルの状態 |
| `ftto_sim/ops.py` | ロボットの基本動作（移動・取る・置く） |
| `ftto_sim/engine.py` | 離散事象シミュレーションの中核 |
| `ftto_sim/policies/dispatch.py` | ロボット作業の優先順位（仮：上流優先） |
| `ftto_sim/policies/exchange.py` | 作業を基本動作の列に展開する手順（入れ替え動作） |
| `ftto_sim/policies/layer_select.py` | 並列層の選択（若い順） |
| `ftto_sim/writers.py` | ログX/A/B/C と真値の記録・出力 |
| `configs/sample.toml` | 設定例（数値は架空） |

- ルールを追加する場合は，クラスを実装して `ftto_sim/policies/__init__.py` に名前を登録すると，設定ファイルの `[policies]` から選べる
- ログCに他の Pos の動作開始・終了を出す場合は，設定の `log.logc_kinds` に Pos の種類を加える（例：`["hand", "process"]`）

### 出力ファイル

| ファイル | 内容 |
|---|---|
| `log_x.csv` | 装置構成 |
| `log_a.csv` | `time, material_id, process_id, cassette_id` |
| `log_b.csv` | `time, material_id, unit_id, pos_id, event(IN/OUT)` |
| `log_c.csv` | `time, unit_id, pos_id, event(START/END), action, target` |
| `truth_occupancy.csv` | マテリアル×Pos ごとの実時刻（IN・処理完了・OUT）と純粋な処理時間 |
| `truth_robot_ops.csv` | ロボットの全動作の実時刻 |
| `truth_summary.json` | Pos ごとの占有時間・処理時間，ロボットごとの稼働時間 |

- ログの時刻は秒単位（`YYYY-MM-DD HH:MM:SS`）．真値の時刻はシミュレーション開始からの秒（小数）
