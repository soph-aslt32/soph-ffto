# 推定アルゴリズム

> 状態：方針はユーザー合意済み（2026-10-31）．実装は未着手．

## 方針

求めたいのは，現状の各部位の**潜在能力**である．実際の投入間隔で流れた結果ではなく，各 Pos にあと何秒早い間隔でマテリアルが来ても，その Pos が律速しないかを，ログから計算だけで求める．

そのため，**投入間隔に左右されない量だけ**から能力を組み立てる．

| 量 | 求め方 | 投入間隔に左右されない理由 |
|---|---|---|
| 取る・置く動作の長さ | ログCの START〜END | 動作の途中で待たないため |
| 移動時間 | 動作の END から次の START までの区間 | 持ったままの移動は，間に待ちが入らないため |
| 処理時間 | 手空きのロボットが動き出した時刻 − 置かれた時刻 | 処理そのものの時間のため |

- **ログCが土台**：時間の計算は，ログCの中の時刻の差で行う．ログ間のラグの影響を受けないようにするため．
- **ログBの役割**：どのマテリアルのどの Pos への動作かを特定する．各 Pos の入場間隔を求める．
- **推測で埋めない**：データが足りない値には印を付け，区間や「未観測」として出す．

### ログBの区間を土台にした旧案をやめた理由

旧案は，ロボットの隣り合うイベントの間隔をログBで測り，入れ替え手順に沿って足していた．しかし入れ替えは，前のマテリアルが処理層に残っているうちに次が届いたときしか起きない．投入間隔だけを変えて試すと，余裕があるほど能力が求められず，値も投入間隔に引きずられた．

| 投入間隔 | R1 の入れ替え回数 | ログBから求めた W（真値 19 s） | 「buffer に置く→load から取る」（真値 7 s） |
|---|---|---|---|
| 70 s | 19108 | 19 s | 7 s |
| 86.4 s | 6066 | 19 s | 7 s |
| 120 s | 0 | 算出不可 | 27 s |
| 200 s | 0 | 算出不可 | 107 s |
| 600 s | 0 | 算出不可 | 507 s |

## 確認済みの前提

| 事実（ユーザー確認済み） | 設計への影響 |
|---|---|
| START〜END に待ちは含まれない．待ちは END から次の START まで | 取る・置く動作の長さを直接測れる |
| PICK は実際に取る動作で，取り始める時刻に START が記録される．取る位置への移動は MOVE で，実ログに記録されない | 移動は END から次の START の間にある．この区間は「移動＋待ち」になる |
| 取る・置く動作は，それぞれ START と END の行がある | 動作の種類ごとに測れる |
| Upper と Lower の動作は基本的に重ならず，役割が分離している（Upper は上流からの受け取り，Lower は処理済みを下流へ運ぶ） | ハンドごとの順序だけで，ログBと対応付けられる |
| 次のマテリアルを持って処理層の前まで移動し，置けなければ移動の後で待つ | 処理完了後の移動が要らない．層の能力は 処理時間 + 取る + 置く になる |
| ログBとログCの時刻は，通信のラグのため完全には一致しない | 時間差は同じログの中で取る |
| 同じ段の層は，同じ処理IDなら処理時間が同じ | 処理時間を段でまとめ，使われない層にも適用できる |
| 処理層の能力には，取る・置く動作の時間を含める | 「あと何秒」を，実際に達成できる値で見る |
| 余裕は，各 Pos にあと何秒早い間隔でマテリアルが来ても，その Pos が律速しないか，の意味 | 基準はログAの取り込み間隔ではなく，その Pos の入場間隔になる |
| 上流からマテリアルが来ているのに処理が終わらず，ロボットが保持して待つのは，余裕ではなく律速の扱い | 保持待ちは余裕に数えず，律速の判定に使う |
| 下流→上流の移動時間は，上流→処理層 と 処理層→下流 の和より長くならない | 待ちと分けられない移動の上界に使える |

## 1. 前処理

### 1.1 構成と経路

- ログXから，Pos の種類と，ハンド→(ロボット, Upper/Lower) の対応を取る．
- ログBから，マテリアルごとに IN/OUT を対にし，Pos の列を作る．経路上で同じ位置に入れ替わりで現れる非ハンドの Pos 群を「段」とする．

### 1.2 動作の対応付け

Upper と Lower は役割が分離しており，各ハンドは取る・置くを交互に繰り返す．MOVE の行も無いので，ハンドごとの動作の並びは，ログBのイベントの並びと一対一に対応する．

- ログBのイベント：ハンド h の取る動作は，h に入る直前の Pos の OUT．置く動作は，h の OUT．属性は (マテリアル m, h, 対象の Pos)．
- ハンドごとに，k 番目の START，k 番目の END，ログBの k 番目のイベントを対応させる．動作名は要らない．同じ秒の中で行の順序が入れ替わっても影響を受けない．
- ロボット単位の動作の順序は，ログBのイベントの時刻で決める．
- 行そのものの欠落があると以降がずれる．START と END の数の不一致や，END < START が続いた場合は，警告して区切り直す．

### 1.3 ログ間のラグ

- 差 = ログCの END − 対応するログBのイベント時刻 を，ロボットごとに集める．
- 中心は平均で取る（打刻が秒単位のため，中央値だと 0 か 1 に丸まる）．ばらつきの幅は，5〜95% 点の差とする．
- ばらつきの幅は，以降の許容幅とする．大きければ警告する．

## 2. 動作の長さと移動時間

### 2.1 取る・置く動作の長さ g

- 型は PICK@Pos，PLACE@Pos とする．
- g は，中央値から ±(1 s + ばらつきの幅) に入る値の平均とする．外乱で伸びた動作を除くため．
- 最小値は使わない．秒の切り捨てと外乱の両方に弱いため．

### 2.2 移動時間

END から次の START までの区間は「移動＋待ち」である．ロボットが持ったまま運ぶ区間には待ちが入らないので，移動時間を直接測れる．

| 移動 | 使う区間 | 間の待ち | 求め方 |
|---|---|---|---|
| 上流→処理層 | 上流で取る END → 処理層に置く START | 無い | 区間の中心 |
| 処理層→下流 | 処理層で取る，または置く END → 下流に置く START | 閉塞が無ければ無い | 区間の中心 |
| 下流→上流 | 下流に置く END → 上流で取る START | 分けられない | 上界 |

下流→上流の上界は，次の小さい方とする．

- 区間の，件数 5 件以上の最小の値 ＋ ばらつきの幅．次のマテリアルが届いていれば待ちが無いので，移動時間そのものになる．
- 上流→処理層 ＋ 処理層→下流．

ロボットが律速に近いほど待ちの無い区間が観測され，値が締まる．余裕があるときは，上界でも判定は変わらない．往復の移動時間は同じとみなす．

## 3. ロボット

ハンドPos の能力は，単独では定義しない．Upper と Lower は腕を共有するので，理論値はロボット1台に対して定義する．

### 3.1 飽和サイクル W_r

入れ替え手順に沿って，動作の長さと移動時間を足す．手順は確認済みの基本手順から作り，差し替えられるようにする．

- 例（R1）：PICK@load 2 ＋ 移動 load→proc1 3 ＋ PICK@proc1 2 ＋ PLACE@proc1 2 ＋ 移動 proc1→buffer 3 ＋ PLACE@buffer 2 ＋ 移動 buffer→load 5 ＝ 19 s
- 入れ替えが1度も起きていなくても計算できる．
- 下流→上流の移動が上界のときは，W_r も上界になる．
- 欠けた型があれば，W_r は「未観測」とし，既知の型の和を下界として出す．
- 並列層で移動時間が層ごとに違う場合は，飽和時に使われる全層で平均する．観測の無い層は，同じ段の値を「借用」する．

### 3.2 待ちの内訳

END から次の START までのうち，移動を除いた時間が，ロボットの待ちである．1枚あたりで次の3つに分ける．ハンドの状態はログBの IN/OUT から分かる．

| 記号 | 待ち | 意味 | 扱い |
|---|---|---|---|
| a | 手空き | 何も持たず，次の動作の対象も無い | 余裕 |
| b | 処理待ち | 何も持たず，処理層の完了を待っている | 余裕 |
| c | 保持待ち | マテリアルを持って，待ち先の Pos が空くのを待っている | 律速の印（第7章） |

b も余裕に数える．間隔を詰めると，ロボットは処理の完了を待たずに次のマテリアルを取りに行き，入れ替えが始まるため．この切り替わりで a と b の内訳は大きく動くが，a + b は投入間隔に沿って連続して減る．

| 投入間隔（処理ID A，R1） | a | b | a + b | 間隔 − 19 s |
|---|---|---|---|---|
| 86.37 s | 27 s | 40 s | 67 s | 67.37 s |
| 70.37 s | 11 s | 40 s | 51 s | 51.37 s |
| 60.37 s | 1 s | 40 s | 41 s | 41.37 s |
| 55.37 s | 0 s | 36 s | 36 s | 36.37 s |
| 52.37 s | 33.2 s | 0 s | 33.2 s | 33.37 s |

注意：次のマテリアルが間に合わず入れ替えが起きないと，真の限界は W_r より b の分だけ長くなる．低負荷のログだけでは区別できない（12.2）．

### 3.3 余裕

- Δ_r = a + b（1枚あたりの中央値）．c が無いときは，入場間隔 − W_r に一致する．
- ρ_r = 1 − Δ_r / 入場間隔．保持待ちは余裕に数えないので，保持待ちが続くと ρ_r は 1 に近づく．

### 3.4 現状の量（参考）

- 実動作時間：窓の中の取る・置く動作の長さと移動時間の合計 ÷ 枚数．
- 入れ替えの割合：処理層で取る動作の直後に，同じ処理層へ置く動作が続く回数の割合．

## 4. ハンドPos

- 能力：c_hand ≡ W_r，ρ_hand ＝ ρ_r，Δ_hand ＝ Δ_r（ロボットとの共有と明記する）
- ハンド固有の値として，次を内訳で出す．
  - 最短保持時間：手順の中で保持している間の動作の和．例：R1 Upper は 移動 3 ＋ PICK 2 ＋ PLACE 2 ＝ 7 s
  - 実保持時間：ログBの IN〜OUT
  - 保持中の待ち：実保持時間 − 最短保持時間．待ち先を付ける
- ハンドへの移動の配分は出さない．約束事であり，能力と誤読されるため．

## 5. 処理時間 s

処理の完了はログに記録されない．ただし，ロボットは処理済みのマテリアルがあれば待たないので，**待っていたロボットが動き出した時刻が，処理の完了にあたる．**

### 5.1 手空きサンプル

取る動作の START から，直前の動作によって次のように求める．

| 直前の動作 | 手空きの判定 | 処理時間のサンプル |
|---|---|---|
| 同じ段に置いた | 区間 ≥ しきい値 | 取る START − 置かれた時刻 |
| 上流で取った（次を持って層の前で待つ） | 区間 − 上流→処理層 ≥ しきい値 | 取る START − 置かれた時刻 |
| 下流に置いた（離れた位置で待つ） | 区間 − 処理層→下流 ≥ しきい値 | 取る START − 移動 − 置かれた時刻 |

- しきい値は 2 s ＋ ばらつきの幅とする．
- 置かれた時刻は，同じマテリアルをその Pos に置いた動作の END である．両方ともログCの時刻なので，ログ間のラグの影響を受けない．
- 3行目は，手空きのロボットがその場で待つ前提である．試算では全体の 3% 以下だった．
- 反応の遅れがあれば処理時間に含まれる．実際にかかる時間なので，能力としては保守側になる．
- 集計：(段, 処理ID) でまとめて中心を取る．層ごとの値も出し，差があれば警告する．

### 5.2 サンプルが足りない場合

処理の完了がロボットの動作中に重なると，手空きサンプルが得られない．投入間隔と処理時間の関係によっては，全マテリアルで起きる．例：投入間隔 86.4 s の proc1/C は，完了がいつも次のマテリアルを取りに行く途中に重なり，手空きサンプルが 0/6020 件だった．

このとき，次の区間が分かる．

- 上界：取る START − 置かれた時刻の中央値．取り始めた時点で処理は終わっていた．
- 下界：最後に手空きだった時刻 − 置かれた時刻の中央値．手空きの間は処理が終わっていなかった．

採用率（手空きサンプル数 ÷ 取る動作の数）で，次のように扱う．しきい値は目安で，検証で見直す．

| 採用率 | 印 | 出力 |
|---|---|---|
| 50% 以上 | 推定 | 手空きサンプルの中心 |
| 0% より大きく 50% 未満 | 推定（偏りの恐れ） | 中心と区間 |
| 0% | 区間のみ | 区間 |

採用率が低いと，処理が長めだったサンプルに偏ることがある．例：投入間隔 200.37 s の proc2/B は採用率 11% で 201.19 s（真値 200 s）だった．一方，カセット間に空きがあると，カセットの最後のマテリアルは次の搬送と重ならないので，採用率 5% でも偏りの無いサンプルが得られる（投入間隔 86.4 s，空き 60 s の proc1/C で 292 件，80.13 s）．

## 6. 部位の能力

### 6.1 処理層 Pos

- c_{p,k} = s_{S,k} + g(PICK@p) + g(PLACE@p)
- ロボットは処理層の前で待つので，処理完了後の移動は含まない．
- s が区間のときは，c も区間で出す．
- 同じ段の層は s を共有する．観測の無い層には段の値を適用し，「借用」の印を付ける．

### 6.2 段（並列層をまとめた単位）

- C_{S,k} = c_{p,k} / |S|．|S| は層の数．前提は「飽和時には全層が使われる」．
- 単層の段で，同じロボットが前後を担う場合は，C ≥ max(c, W_r) とする．
- 処理IDが材料ごとに混ざる場合：C_S(K) = 窓の中の材料の C_{S,k(m)} の平均

### 6.3 コンベア Pos

- ロボット間のコンベア：c = 搬送時間 + g(次のロボットの PICK) + g(前のロボットの PLACE)
- 先頭段：c = 搬送時間 + g(PICK)
- 最終段：c = 滞在時間（ハンドの OUT〜自分の OUT，いずれもログB）の中心 + g(PLACE)
- 自動搬送（feed=auto）：滞在時間の下限側の値を使い，「上界のみ」とする．
- 搬送時間は，手空きサンプルの取る START − 置かれた時刻 で求める．次のロボットが離れた位置で待っていると移動時間が混ざるので，「上界のみ」とする．先頭段はログAの時刻にラグを足して使う．

## 7. 余裕と律速の判定

### 7.1 余裕

- Δ_i,K = T_{i,K} − C_i(K)．1枚あたりの，その Pos が動いていない時間にあたる．ロボットは 3.3 の値を使う．
- ρ_i,K = 1 − Δ_i,K / T_{i,K}
- T_{i,K}：カセット K の中での，その Pos の連続する入場の間隔の平均．
  - カセットの中だけで計算するので，カセット間の空きは含まれない．
  - 中央値は使わない．並列層では投入が束になるため，実際の間隔より短くなる（処理ID A の飽和時で，実際 51.33 s に対して中央値 45 s）．
  - 3 × 中央値を超える間隔（停止など）は除く．
- ログAの取り込み間隔は，基準に使わない．

### 7.2 律速の判定

保持待ち c は，上流からマテリアルが来ているのに，待ち先の Pos が空かないことを示す．定常状態では，投入間隔が待ち先の能力より短いときにだけ続けて現れる．

- 待ち先：保持待ちの次の動作の対象の Pos．
- 判定：カセットの過半の枚数で保持待ちが出ている待ち先のうち，**最も下流のもの**を律速部位とする．律速の手前は順に詰まり，上流のロボットも下流の閉塞で保持待ちになるため．
- 保持待ちが無ければ「律速なし」とする．

この判定は，能力の計算に依存せず，ログから直接得られる．能力から予測した律速部位と比べて使う．

- 予測：b_K^th ＝ argmax_i C_i(K)，および2位との差
- 観測：b_K^obs ＝ 上の判定
- 一致しない場合：前のカセットの詰まりが残っている「過渡」か，干渉またはモデルの誤りである．直前のカセットで律速があれば「過渡」の印を付ける．

## 8. カセット窓とライン全体

- **能力は1か月分をまとめて**，(Pos/段, 処理ID) ごとに求める．カセットごとに求めるのは，T，ρ，Δ，待ちの内訳，律速の判定．能力が変わっていないかは，動作の長さと処理時間の中心をカセット（または週）ごとの時系列で監視する．
- **窓**：部位 i ごとにずらす．W_{i,K} = [t_i(K の最初の材料), t_i(K+1 の最初の材料))．t_i はその部位に入った時刻．ロボットの動作は，対象の材料に帰属させる．
- **ライン限界**：処理ID（カセット）ごとに，T_line^min(K) = max_i C_i(K)．i は全ての段，全てのロボット，全てのコンベア．
- **値の無い部位を max から除かない．** 区間の部位があれば T_line^min も区間で出し，律速部位が確定しないときはそう明記する．「未観測」の部位があれば，値は「下限のみ」とする．除くと限界を過小評価する（投入間隔 86.4 s の C で，真値 83.99 s に対して 81.34 s，律速部位も誤り）．
- **月全体**：Σ n_K max_i C_i(K) / Σ n_K．max を取ってから平均する．部位ごとの余裕は，枚数で重み付けした平均と最小を出す．
- **出力の意味**：ライン限界は「この間隔より短くすると，少なくともこの部位が能力を超える」という**下限**である．入れ替えが起きない場合や，部位間の干渉がある場合は，実際の限界はこれより長い．
- **校正**：律速が観測されたカセットでは，実測の間隔 T* を予測と比べ，比 κ を出す．**κ は同じ (処理ID, 律速部位) にだけ適用する．** 律速が観測されたカセットが無ければ「未校正（楽観的な可能性あり）」と明示する．
- **拮抗の警告**：C の上位2つの比が 0.95 以上で，間の保持枠（コンベア＋ハンド）が2枚以下なら，限界を「下限値」として扱う．

## 9. 品質の印

| 印 | 意味 |
|---|---|
| 推定 | 十分なサンプルで求めた値 |
| 推定（偏りの恐れ） | 採用率が低い．区間を併記する |
| 区間のみ | 手空きサンプルが無く，下界と上界だけが分かる |
| 上界のみ／下限のみ | 片側だけが分かる（下流→上流の移動を含む W_r など） |
| 借用 | 同じ段の他の層の値を使った |
| 未校正 | 律速が観測されたカセットが無い |
| 過渡 | 前のカセットの詰まりが残っている |
| 未観測 | 推定できない．推測では埋めない |

## 10. ログだけでは分からないもの

- 投入間隔が長いと使われない層の個別の能力．段の値を借用するので，層ごとの差は検出できない．
- 飽和時にだけ現れる動作（退避など）．
- 入れ替えが起きるかどうか．低負荷では，次のマテリアルが間に合うか分からない．
- 干渉による損失（κ）．律速が観測されたカセットが無ければ未校正になる．
- 手空きのまま動く時間．手空きの移動が待ちと分けられないため，下流→上流の移動は上界にとどまる．

## 11. 生成器の修正

ログCの待ちの記録方式を追加する項目は，START〜END に待ちが含まれないと確認できたので不要になった．層ごとの処理時間の上書きも，同じ段の層は処理時間が同じと確認できたので不要になった．

実装済み（2026-10-31）：

- ログCに MOVE を出さない（`log.logc_moves`）．真値には MOVE を残す．
- 置き先が処理中なら，マテリアルを持って置き先の前まで移動して待つ（`policies.dispatch`．比較用に，上流で待つ `upstream_first_wait_at_source` も選べる）．
- ログ間のラグ（`log.logc_lag_offset_s`，`log.logc_lag_jitter_s`）．
- 真値の拡充：`truth_capacity.json`，`truth_robot_waits.csv`，`truth_intake.csv`，`truth_robot_ops.csv` の対象マテリアル．

未実装：

1. ログの並び順の修正：writers.fmt は，打刻した秒の値と，記録に追加した順で並べている．基本は (秒, 実際の時刻) で並べ，検証用に，同じ秒の中の順序を乱すオプションと，START/END の行そのものを欠落させるオプションを追加する．
2. ログBの打刻の選択肢：OUT・IN を PICK/PLACE の開始と完了のどちらで打つか，ラグを下流の IN と上流の OUT のどちらに乗せるか．
3. 入力のスケジュールの拡張：カセットごとに投入間隔と処理IDを指定できるようにする（例：input.interval_schedule）．1か月の中に低負荷と高負荷を混ぜ，κ の校正を検証するため．
4. ロボットの動作時間のばらつき（jitter）と外乱を与えられるようにする．処理の開始の遅れ（IN から処理開始まで）のオプションを追加する．
5. 検証専用の補助スクリプト：処理IDを固定して過負荷で走らせ，T_true^min(k) と真のボトルネックを求める．推定側からは使わない．

### 12.2 試算で分かった制約

低負荷で見える値が同じでも，真の限界が異なる場合がある．処理を 3 s に短くした設定では，投入間隔 40.37 s の a と b が同じなのに，真の限界は次のように分かれた．

| 設定 | a | b | 真の限界 |
|---|---|---|---|
| コンベアは既定（buffer 10 s） | 17 s | 3 s | 22 s |
| コンベア 1 s | 17 s | 3 s | 19 s |

前者は次のマテリアルが間に合わず入れ替えが起きないので，限界が W_r より b の分だけ長い．処理時間が W_r より十分長いサンプル設定では，この差は問題にならなかった．

秒の切り捨ての影響：投入間隔と動作時間がきりのよい値だと位相が揃い，平均で打ち消せない．処理層の能力が最大 0.5 s，W が 2% 程度ずれる．実ログでは未確認である．

ロボットの動作時間のばらつき，外乱，行そのものの欠落，動作の順序の乱れは未検証である．

### 12.3 検証計画

- **真値**
  - T1（要素）：設定値，truth_occupancy，truth_robot_ops，truth_robot_waits
  - T2（合成値）：truth_capacity.json
  - T3（ライン限界）：処理IDを固定して投入間隔を極小にした飽和実行で求める．
  - 真の ρ と Δ は，推定と同じ窓の定義で計算する．
- **条件**
  - **投入間隔：限界より十分長い条件を必ず含める．** 55 / 62 / 70 / 86.4 / 120 / 200 / 600 s と，きりの悪い値
  - 処理IDの付け方：per_cassette / per_material
  - カセット間の空き：0 / 60 s
  - ログ間のラグ：一定（正負）／行ごとのばらつき
  - ログBの打刻：ラグの大きさと乗る側
  - 行そのものの欠落，同じ秒の中の行順の入れ替え
  - ロボットの動作時間のばらつきと外乱
  - 低負荷だけの1か月と，低負荷・高負荷が混ざった1か月
- **指標**（目安．合意が必要）
  - 動作の長さの誤差 ≤ 0.2 s，W の誤差 ≤ 2%（上界の分を除く），処理時間の誤差 ≤ 1 s
  - ρ の誤差 ≤ 0.02，Δ の誤差 ≤ 1 s
  - カセットごとの律速の一致率
  - T_line^min ÷ T_true（楽観の度合い）
  - 印の正しさ：区間に真値が入っているか，「未観測」の判定が妥当か
- **投入間隔への不変性**：投入間隔だけを変えても，同じ部位の能力の推定値が動かないことを確かめる．
- **最重要試験**：限界より十分長い投入間隔の1か月ログだけから，A/B/C の限界とボトルネックをどこまで再現できるか．

## ユーザー確認事項

| 項目 | 回答 |
|---|---|
| Q1. 待ちはログCのどこに入るか | START〜END には入らない．END から次の START までが待ち |
| Q2. 動作の粒度と重なり | 取る・置く動作は別々の行で，それぞれ START と END がある．MOVE は記録されない．Upper と Lower の動作は基本的に重ならない |
| Q3. ログBとログCの時刻 | 通信のラグのため，完全には一致しない．ばらつきの影響は小さいと分かったので質問を取り下げた．実データで幅を測り，大きければ警告する |
| Q4. 処理層の理論値と待機位置 | 取る・置く動作を含める．次のマテリアルを持って処理層の前まで移動し，移動の後で待つ |
| Q5. 余裕の基準 | ログAの取り込み間隔ではない．各 Pos にあと何秒早い間隔でマテリアルが来ても，その Pos が律速しないか，の意味．カセットの中の入場間隔を使うので，外部の設定値や長い空きの扱いは不要になった |
| Q6. 同じ段の並列層 | 同じ処理IDなら，処理時間は同じとみなしてよい |
| Q7. 移動の時間 | PICK は実際に取る動作で，着いて取り始める時刻に START が記録される．移動は END から次の START の間にある |
| Q8. 待ちの扱い | 上流からのマテリアルを保持して待つのは，余裕ではなく律速の扱い．何も持たない処理待ちは，明示の回答が無いので，試算に基づき余裕に数える（3.2） |
| Q9. 戻りの移動 | 上流→処理層 と 処理層→下流 の和より長くならない |

## 採用しなかった案

| 案 | 理由 |
|---|---|
| ログBの隣り合うイベントの間隔を区間とし，入れ替え手順に沿って足して W を求める（旧案の中心） | 投入間隔が長いと入れ替えが観測できず算出できない．区間の値も投入間隔に引きずられる（120 / 200 / 600 s で 27 / 107 / 507 s，真値 7 s）． |
| 連続する置き完了の間隔を，処理層の能力の主な値にする（旧案の c^eff） | 入れ替えの成立が前提で，余裕のある部位ほどサンプルが得られない．処理時間と動作の長さの和に置き換える． |
| 余裕の基準をログAの取り込み間隔にする | 余裕は，各 Pos に来る間隔に対して，その Pos が律速しないかの意味である（ユーザー確認）． |
| 保持待ちを余裕に数える（手空き＋処理待ち＋保持待ち） | 上流からマテリアルが来ているのに待つのは，余裕ではなく律速の扱い（ユーザー確認）．実際，保持待ちは投入間隔が能力より短いときにだけ続けて現れた． |
| 手空きだけを余裕にする | 投入間隔を詰めると入れ替えが始まり，内訳が大きく動く（処理ID A の R1 で 27→1→0→33 s）．ロボットの能力を表さない．手空き＋処理待ちは連続して減る． |
| 入場間隔を中央値で求める | 並列層では投入が束になり，実際の間隔より短くなる（51.33 s に対して 45 s）．カセットの中の平均を使う． |
| 時刻の近さでログCの動作をログBのイベントへ割り当てる | 行ごとのラグが大きいと判定を誤る（0〜3 s で約 92%）．ハンドごとの順序で対応させれば全件一致する． |
| ログCの END とログBの時刻の完全一致で動作を特定する | ログ間にラグがあり，一致しない． |
| 値の無い部位を除いて max を取る | 限界を過小評価し，律速部位も誤る（86.4 s の C で 81.34 s，真値 83.99 s）．区間のまま max を取る． |
| 動作の長さの最小値を使う | 秒の切り捨てと外乱に弱い．中心を使う． |
| ログCの稼働の割合を ρ とする | 現在の負荷での稼働であり，能力に対する負荷ではない．参考値としてだけ出す． |
| δ_resp(ρ) を a·ρ/(1−ρ) などの関数形で回帰し，不動点を解いて保守側の限界とする | 関数形を決め打ちし，低ρ側から外挿している．ログから計算しただけとは言えず，推測が入る． |
| 現在の負荷での待ちを能力に足す | 待ちは負荷によって変わるので，能力の値にはならない．待ちは内訳として別に出す． |
| 飽和したカセットで学習した補正係数 κ を，他の処理IDやボトルネックの種類にも当てはめる | 根拠の無い外挿．κ は同じ (処理ID, 律速部位) にだけ適用する． |
| 指定の取り込み間隔を，カセット内の取り込み間隔の最頻値で推定し，入口詰まりの判定に使う | カセット全体が飽和していると，飽和した間隔そのものを指定値と誤認する．判定は保持待ちで行う． |
| ロボットの理論値を『観測されたサイクル型のうち最小のもの』とする | 高負荷では維持できない型を選ぶ恐れがある．確認済みの入れ替え手順から作った和を主な値とする． |
| ハンドへの移動の配分を，ハンドPos の能力として出す | 配分は約束事で，能力と誤読される．ハンドの能力はロボットの値を共有する． |
| 滞在時間分布の左端（下側の分位点）を，純粋な処理時間の点推定とする | 待ちの最小値が 0 にならない (Pos, k) で系統的にずれる．手空きサンプルで求める． |
| 待ち時間行列（KLM の拡張），状態分解（WORK/HANDLE/BLOCK/STARVE）を，ボトルネック判定の主な手段とする | 低負荷では矢印が投入側を指す．律速の判定は，保持待ちが続いている部位で行う． |
| 全部位に共通の時刻窓，またはログAの取り込みを基準にした窓で，カセットごとの ρ を出す | 装置内に仕掛かりがたまる余地があるため，上流が先に進み，ρ>1 が出る．部位ごとにずらした窓と，マテリアルの帰属で集計する． |
| 処理IDの構成比で平均した c から max を取る | 楽観的に偏る（61 s に対し，実測は 63.1 s）．カセット（処理ID）ごとに max を取ってから，枚数で重み付けして平均する． |
