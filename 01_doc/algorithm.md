## 方針

求めたいのは，現状の各部位の**潜在能力**である．実際の投入間隔で流れた結果ではなく，本来どこまで短い間隔に対応できるかを，ログから計算だけで求める．

そのため，**投入間隔に左右されない量だけ**から能力を組み立てる．

| 量 | 求め方 | 投入間隔に左右されない理由 |
|---|---|---|
| 動作の長さ g | ログCの START〜END | 動作の途中で待たないため |
| 処理時間 s | 手空きのロボットが動き出した時刻 − 置かれた時刻 | 処理そのものの時間のため |

- **ログCが土台**：ロボットの能力と処理時間は，ログCの時刻から求める．
- **ログBの役割**：どのマテリアルのどの Pos への動作かを特定し，動作名の欠落を補う．ログBの IN 間隔は投入間隔そのものなので，能力の計算に使わない．
- **時間差は同じログの中で取る**：ログBとログCのラグの影響を受けないようにする．
- **推測で埋めない**：データが足りない値には印を付け，区間や「未観測」として出す．

### ログBを土台にした旧案をやめた理由

旧案は，ロボットの隣り合うイベントの間隔をログBで測り，入れ替え手順に沿って足していた．しかし入れ替えは，前のマテリアルが処理層に残っているうちに次が届いたときしか起きない．投入間隔だけを変えて試すと，余裕があるほど能力が求められず，値も投入間隔に引きずられた．

| 70 s | 19108 | 19 s | 7 s |

| 120 s | 0 | 算出不可 | 27 s |

## MOVE 未記録への対応と余裕の定義（提案，未合意）

- 本文の g(MOVE) は，以下の移動時間に読み替える．10.1 の試算は MOVE の行がある前提で行ったものである．

### 動作の対応付け

Upper と Lower は役割が分離しており，各ハンドは取る・置くを交互に繰り返す．MOVE の行も無いので，ハンドごとの動作の並びは，ログBのイベントの並びと一対一に対応する．

- ハンドごとに，k 番目の START，k 番目の END，ログBの k 番目のイベントを対応させる．
- 動作名は要らない．ログ間のラグがあっても崩れない．
- 行そのものの欠落があると以降がずれるので，検出して区切り直す．

### 移動時間の追跡

前提：移動は，取る・置く動作の START〜END の外にある（Q7）．END から次の START までが「移動＋待ち」になる．

| 移動 | 使う区間 | 間の待ち | 求め方 |
|---|---|---|---|
| 上流→処理層 | 上流で取る END → 処理層に置く START | 無い | 区間の中心 |
| 処理層→下流 | 処理層で取る，または置く END → 下流に置く START | 閉塞が無ければ無い | 区間の中心 |
| 下流→上流 | 下流に置く END → 上流で取る START | 分けられない | 上界 |

- 下流→上流の上界：次の小さい方とする．
  - 区間の，件数 5 件以上の最小の値 ＋ ばらつきの幅．次のマテリアルが届いていれば待ちが無いので，移動時間そのものになる．
  - 上流→処理層 ＋ 処理層→下流．往復の移動時間が同じで，遠回りより遠くならない前提（Q9）．
- W_r は上界になる．ただし，ロボットが律速に近いほど待ちの無い区間が観測され，値が締まる．余裕があるときは，上界でも判定は変わらない．
- 処理層の能力は取る・置く動作だけで決まるので，MOVE が無くても影響を受けない．

### 処理時間

待っていたロボットが動き出した時刻は，直接は見えない．取る動作の START から，直前の動作によって次のように求める．

| 直前の動作 | 手空きの判定 | 処理時間のサンプル |
|---|---|---|
| 同じ段に置いた | 区間 ≥ しきい値 | 取る START − 置かれた時刻 |
| 上流で取った（次を持って層の前で待つ） | 区間 − 上流→処理層 ≥ しきい値 | 取る START − 置かれた時刻 |
| 下流に置いた（離れた位置で待つ） | 区間 − 処理層→下流 ≥ しきい値 | 取る START − 移動 − 置かれた時刻 |

3行目は，手空きのロボットがその場で待つ前提である．試算では全体の 3% 以下で，除いても採用率はほとんど変わらない．

### 余裕の定義

- Δ_i = その Pos の入場間隔 − C_i．1枚あたりの，その Pos が動いていない時間にあたる．
- 集計は1枚ごとの値の中央値とする．このため，長い空きは自動的に除かれ，外部の設定値も要らない（旧 Q5 の (2)(3)）．

ロボットについては，1枚あたりの待ちを3つに分ける．

| 記号 | 待ち | 意味 |
|---|---|---|
| a | 手空き | 何も持たず，次の動作の対象も無い |
| b | 処理待ち | 何も持たず，処理層の完了を待っている |
| c | 保持待ち | マテリアルを持って待っている |

入場間隔 − W_r ＝ a + b + c である．ユーザーの例（何も持たず，次の動作も始めようとしていない時間）に最も近いのは a だが，b を含めるかは Q8 で確認する．

- 提案：主な値を a + b + c とし，a を確実な下限として併記する．
- 理由：a は投入間隔によって動き，ロボットの能力を表さない（下の表の R2）．a + b + c は投入間隔によらず一定である．
- 注意：次のマテリアルが間に合わず入れ替えが起きないと，真の限界は W_r より b の分だけ長くなる．低負荷のログだけでは区別できない．

## 1. 前処理

### 1.1 構成と経路

- ログXから，Pos の種類と，ハンド→(ロボット, Upper/Lower) の対応を取る．
- ログBから，マテリアルごとに IN/OUT を対にし，Pos の列を作る．経路上で同じ位置に入れ替わりで現れる非ハンドの Pos 群を「段」とする．

### 1.2 ログCの動作列

- ロボット単位で両ハンドの行を時刻順に並べ，k 番目の START と k 番目の END を対にする．ロボットは同時に1動作なので，同じ秒の中で行の順序が入れ替わっても影響を受けない．
- 前提の確認：Upper と Lower の START〜END が重なると成り立たない（Q2）．実データで重なりの割合を測り，1% を超えたら止めて確認する．
- 行そのものの欠落を検出する：END < START となる対や，長さが極端に外れる対が続いたら，警告して対応付けをやり直す．

### 1.3 ログ間のラグ δ_r

- 動作名が記録されている PICK/PLACE 行の END と，対応するログBのイベントの時刻の差を，ロボットごとに集める．
- 対応するイベントは，PICK が搬送元の OUT，PLACE がハンドの OUT である．打刻が動作のどの時点でも δ_r に吸収されるが，PICK と PLACE で分けて測り，差があれば警告する．
- δ_r は平均で求める（中央値は使わない）．打刻は秒単位なので，中央値だと 0 か 1 に丸まり，直前の MOVE と同点になって判定を誤る．
- ばらつきの幅は，差の分布の 5〜95% 点の差とする．以降の許容幅はこの値から決める．

### 1.4 ログBのイベントと動作の割り当て

- ロボットのイベント列 E_r：ログBから作り，時刻順に並べる．
  - PICK：ハンド h に入る直前の Pos P の OUT．属性は (m, h, P)
  - PLACE：ハンド h の OUT．属性は (m, h, 置き先の Pos Q)
- 各イベントを，同じハンドの動作のうち，END が t + δ_r ± w に入る最も近いものへ，順序を保って割り当てる．w は 1.5 s + ばらつきの幅とする．
- 動作名が記録されている行は，名前が一致するものだけを候補にする．
- 割り当てられなかった動作を MOVE とする．移動元と移動先は，前後の PICK/PLACE の Pos から決める．
- 自己検証：動作名がある行の一部を隠して判定し，正解率を出力する．

## 2. ロボット

ハンドPos の能力は，単独では定義しない．Upper と Lower は腕を共有するので，理論値はロボット1台に対して定義する．

### 2.1 動作の長さ g_r(a)

- 動作の型 a は，PICK@Pos，PLACE@Pos，MOVE 移動元→移動先 とする．
- g_r(a) は，中央値から ±(1 s + ばらつきの幅) に入る値の平均とする．外乱で伸びた動作を除くため．
- 最小値は使わない．秒の切り捨てと外乱の両方に弱いため．

### 2.2 飽和サイクル W_r

入れ替え手順に沿って，動作の長さを足す．手順は確認済みの基本手順から作り，差し替えられるようにする．

- W_r = Σ_{a∈手順} g_r(a)
- 例（R1）：PICK@load 2 ＋ MOVE load→proc1 3 ＋ PICK@proc1 2 ＋ PLACE@proc1 2 ＋ MOVE proc1→buffer 3 ＋ PLACE@buffer 2 ＋ MOVE buffer→load 5 ＝ 19 s
- 入れ替えが1度も起きていなくても，動作が別々に観測されていれば計算できる．
- 欠けた型があれば，W_r は「未観測」とし，既知の型の和を下界として出す．
- 並列層で移動時間が層ごとに違う場合は，飽和時に使われる全層で平均する．観測の無い層は，同じ段の値を「借用」する．
- 照合：入れ替えが観測されていれば，実測の1周と比べる．一致しなければ手順の誤りとして警告する．

### 2.3 現状の量

- 実動作時間：窓の中の動作の長さの合計 ÷ 枚数．現在の作業パターンでの値で，W_r とは別に参考として出す．
- 入れ替えの割合 f_ex：PICK_lower@p の直後に PLACE_upper@p が続く回数の割合．
- 稼働の割合：動作の長さの合計 ÷ 時間．現在の負荷での実際の稼働であり，能力に対する負荷ではない．

### 2.4 待ちの内訳

END から次の START までを待ちとし，1 s を超えるものを，次の動作の対象の状態（ログB）で分ける．

- 次が PICK@P：P が空なら「到着待ち（上流）」，処理中なら「処理待ち（P）」
- 次が PLACE@Q：Q が埋まっていれば「下流の閉塞（Q）」
- どちらでもない：「仕事なし」

### 2.5 ρ と余裕

- ρ_r = W_r / T，Δ_r = T − W_r

## 3. ハンドPos

- 能力：c_hand ≡ W_r，ρ_hand ＝ ρ_r，Δ_hand ＝ Δ_r（ロボットとの共有と明記する）
- ハンド固有の値として，次を内訳で出す．
  - 最短保持時間：手順の中で保持している間の動作の和．例：R1 Upper は MOVE 3 ＋ PICK 2 ＋ PLACE 2 ＝ 7 s
  - 実保持時間：ログBの IN〜OUT
  - 保持中の待ち：実保持時間 − 最短保持時間．待ち先（処理の完了か，置き先の空きか）を付ける
- ハンドへの MOVE の配分は出さない．約束事であり，能力と誤読されるため．

## 4. 処理時間 s

処理の完了はログに記録されない．ただし，待ちが END から次の START までに限られるので，**待っていたロボットが動き出した時刻が，処理の完了にあたる．**

### 4.1 手空きサンプル

マテリアル m の PICK@P について，次で求める．

- 応答の開始 t_r：PICK の START．直前に待ち無しで続く MOVE があれば，その MOVE の START
- 手空きの判定：t_r − 直前の動作の END ≥ 2 s ＋ ばらつきの幅
- s のサンプル：t_r − (m を P に置いた PLACE の END)

両方ともログCの時刻なので，ログ間のラグの影響を受けない．先頭段は置く動作が無いので，ログAの時刻に δ_r を足す．

- 前提：ロボットは，処理済みのマテリアルがあれば待たない．反応の遅れがあれば s に含まれる．実際にかかる時間なので，能力としては保守側になる．
- 集計：(段, 処理ID) でまとめて g と同じ方法で中心を取る．層ごとの値も出し，差があれば警告する．
- コンベアの搬送時間も，同じ方法で求める．

### 4.2 サンプルが足りない場合

処理の完了がロボットの動作中に重なると，手空きサンプルが得られない．投入間隔と処理時間の関係によっては，全マテリアルで起きる．例：投入間隔 86.4 s の proc1/C は，完了がいつも次のマテリアルを取りに行く途中に重なり，手空きサンプルが 0/6020 件だった．

このとき，全マテリアルについて次の区間が分かる．

- 上界 s^up：PICK の START − 置かれた時刻の中央値．取り始めた時点で処理は終わっていた．
- 下界 s^lo：最後に手空きだった時刻 − 置かれた時刻の中央値．手空きの間は処理が終わっていなかった．

採用率（手空きサンプル数 ÷ PICK の数）で，次のように扱う．しきい値は目安で，検証で見直す．

| 採用率 | 印 | 出力 |
|---|---|---|
| 50% 以上 | 推定 | 手空きサンプルの中心 |
| 0% より大きく 50% 未満 | 推定（偏りの恐れ） | 中心と，区間 [s^lo, s^up] |
| 0% | 区間のみ | 区間 [s^lo, s^up] |

採用率が低いと，処理が長めだったサンプルに偏る．例：投入間隔 200.37 s の proc2/B は採用率 11% で 201.19 s（真値 200 s）だった．一方，カセット間に空きがあると，カセットの最後のマテリアルは次の搬送と重ならない．採用率 5% でも偏りの無いサンプルが得られる（投入間隔 86.4 s，空き 60 s の proc1/C で 292 件，80.13 s）．

## 5. 部位の能力

### 5.1 処理層 Pos

- c_{p,k} = s_{S,k} + g(PICK@p) + g(PLACE@p)
- ロボットは処理層の前で待つので，処理完了後の移動は含まない．
- s が区間のときは，c も区間で出す．
- 同じ段の層は s を共有する．観測の無い層には段の値を適用し，「借用」の印を付ける．
- ρ_p,K = c の平均 / その層の入場間隔，Δ_p ＝ その層の入場間隔 − c．若い順の振り分けで負荷が偏るので，個々の層の値は参考にとどめる．

### 5.2 段（並列層をまとめた単位）

- C_{S,k} = c_{p,k} / |S|．|S| は層の数．前提は「飽和時には全層が使われる」．
- 単層の段で，同じロボットが前後を担う場合は，C ≥ max(c, W_r) とする．
- 処理IDが材料ごとに混ざる場合：C_S(K) = 窓の中の材料の C_{S,k(m)} の平均
- ρ_S,K = C_S(K) / T_K，Δ_S,K = T_K − C_S(K)

### 5.3 コンベア Pos

- ロボット間のコンベア：c = s + g(次のロボットの PICK) + g(前のロボットの PLACE)
- 先頭段：c = s + g(PICK)
- 最終段：c = 滞在時間（ハンドの OUT〜自分の OUT，いずれもログB）の中心 + g(PLACE)
- 自動搬送（feed=auto）：滞在時間の下限側の値を使い，「上界のみ」とする．

## 6. カセット窓

- **能力は1か月分をまとめて**，(Pos/段, 処理ID) ごとに求める．カセットごとに求めるのは，T，ρ，Δ，待ちの内訳，f_ex，飽和の印．能力が変わっていないかは，g と s の中心をカセット（または週）ごとの時系列で監視する．
- **窓**：部位 i ごとにずらす．W_{i,K} = [t_i(K の最初の材料), t_i(K+1 の最初の材料))．t_i はその部位に入った時刻．ロボットの動作は，対象の材料に帰属させる．
- **T の求め方**
  - T_K^in：ログAの取り込み間隔の，定常部での中央値
  - T_{i,K}^own：その部位自身の入場間隔の中央値（先頭の q 枚を除く．q は段の層数）
- **Δ の基準**：主な値は T_K^in で計算し，T^own による値も併記する（Q5）．部位が飽和しているカセットでは Δ<0 となる．
- **長い空き**（3 × 中央値の T を超えるもの）：窓から除き，「空き」として別に出す（Q5）．
- **処理IDが切り替わるカセットの先頭**：過渡状態として「定常部のみ」と「全体」の両方を出す．
- **ボトルネックの推移**：カセットごとに次を出す．
  - b_K^th ＝ argmax_i C_i(K)/T_K，および2位との差
  - b_K^obs ＝ 待ちの内訳で最も多く待たれた部位
  - 飽和の印
  - b^th と b^obs が一致しない場合は，干渉またはモデルの誤りの印を付ける．低負荷では b^obs が投入側を指すので，診断にとどめる．

## 7. ライン全体

- 処理ID（カセット）ごとに，T_line^min(K) = max_i C_i(K)．i は全ての段，全てのロボット，全てのコンベア．
- **値の無い部位を max から除かない．** 区間の部位があれば T_line^min も区間 [max_i C_i^lo, max_i C_i^up] で出し，律速部位が確定しないときはそう明記する．「未観測」の部位があれば，値は「下限のみ」とする．除くと限界を過小評価する（投入間隔 86.4 s の C で，真値 83.99 s に対して 81.34 s，律速部位も誤り）．
- 月全体：Σ n_K max_i C_i(K) / Σ n_K．**max を取ってから平均する．**
- ライン全体の余裕：Δ_line,K = T_K^in − T_line^min(K)
- 楽観的な偏りへの対処
  1. 処理IDごとに max を取ってから平均する．
  2. 単層の段とロボットの結合を max で表す（5.2）．
  3. 飽和の実測で校正する．飽和したカセットは，部位自身の入場間隔が上流より長い状態が続く，上流の滞在時間が増える，取り込みが待たされる，のいずれかで判定する．取り込み間隔だけでは判定できない（上流で待つ動作の試算では，投入間隔 86.4 s が C の限界 87 s より短くても，20枚のカセットでは取り込みが遅れなかった）．実測の限界 T* との比 κ を出し，**同じ (処理ID, ボトルネック部位) にだけ適用する．** 飽和したカセットが無ければ「未校正（楽観的な可能性あり）」と明示する．
  4. 拮抗の警告：C の上位2つの比が 0.95 以上で，間の保持枠（コンベア＋ハンド）が2枚以下なら，限界を「下限値」として扱う．
- 出力の意味は「この間隔より短くすると，少なくともこの部位が能力を超える」という**下限**である．

## 8. 品質の印

| 印 | 意味 |
|---|---|
| 推定 | 十分なサンプルで求めた値 |
| 推定（偏りの恐れ） | 採用率が低い．区間を併記する |
| 区間のみ | 手空きサンプルが無く，下界と上界だけが分かる |
| 上界のみ／下限のみ | 片側だけが分かる |
| 借用 | 同じ段の他の層の値を使った |
| 未観測 | 推定できない．推測では埋めない |

## 9. ログだけでは分からないもの

- 投入間隔が長いと使われない層の個別の能力．段の値を借用するので，層ごとの差は検出できない．
- 飽和時にだけ現れる動作（退避など）．
- 干渉による損失（κ）．飽和したカセットが無ければ未校正になる．
- 一度も実行されない移動（例：飽和時にだけ通る経路）．W_r が「未観測」になる．

## 10. 検証

### 10.1 試算の結果（2026-10-31）

実装前の確認として，修正案を試作し，サンプル設定で投入間隔を変えた30日分のログで試した．処理層の前で待つ動作は，生成器のルールを実行時に差し替えて模擬した．真の限界は，処理IDを固定して投入間隔 1 s で飽和させて求めた．

| 投入間隔 | W（真値 19 s） | 限界 A（真値 51.34 s） | 限界 B（真値 68.02 s） | 限界 C（真値 83.99 s） |
|---|---|---|---|---|
| 70 s | 19.0 s | 51.33 s | 67.99 s | 84.00 s |
| 86.4 s | 19.0 s | 51.34 s | 68.00 s | 区間 81.34〜86 s |
| 86.4 s（カセット間の空き 60 s） | － | － | － | 84.13 s |
| 137.37 s | 19.0 s | 51.33 s | 68.00 s | 84.00 s |
| 600.37 s | 19.0 s | 51.34 s | 67.98 s | 84.02 s |

律速部位は，A・B が proc2，C が proc1 である．70 s の行だけ，行ごとに 0〜1 s のラグを与えている．カセット間の空き 60 s の行は，手空きサンプルの処理時間 80.13 s（採用率 5%）に取る・置く動作の 4 s を足した値である．

ログBとログCのラグの影響は次のとおり（動作名の欠落 50%）．欠落 90% は，ラグなしと行ごとに 0〜1 s の条件で確かめ，判定と結果は 50% のときと変わらなかった．

| ラグ | 動作の判定 | W | 限界のずれ |
|---|---|---|---|
| 一定（±3 s） | 100% | 19.0 s | 変化なし |
| 行ごとに 0〜1 s | 100% | 18.99〜19.01 s | 0.01 s 程度 |
| 行ごとに 0〜3 s | 約 92% | 19.32〜19.40 s | 最大 0.28 s |

秒の切り捨ての影響：投入間隔と動作時間がきりのよい値だと位相が揃い，平均で打ち消せない．動作時間 3.4 / 2.3 / 1.7 s で W の真値 19.8 s に対し，投入間隔 600 s では R1 が 19.4 s だった．投入間隔 600.37 s では 19.8 s になる（この確認は上流で待つ動作で行った）．

有利な条件での結果である点に注意する．ロボットの動作時間にばらつきと外乱が無く，行そのものの欠落も無い．動作名がすべて欠落する場合はラグを測れないので，未検証である．

### 10.2 検証計画

- **真値**
  - T1（要素）：設定値，truth_occupancy，truth_robot_ops
  - T2（合成値）：生成器が設定から計算する truth_capacity.json．c，C_S，W，手順
  - T3（ライン限界）：検証専用に，処理IDを固定して投入間隔を極小にした飽和実行を行い，T_true^min(k) と真のボトルネックを求める．
  - 真の ρ と Δ は，推定と同じ窓の定義で計算する．
- **条件**
  - **投入間隔：限界より十分長い条件を必ず含める．** 55 / 62 / 70 / 86.4 / 120 / 200 / 600 s と，きりの悪い値
  - 処理IDの付け方：per_cassette / per_material
  - カセット間の空き：0 / 60 s
  - 動作名の欠落：0 / 0.5 / 0.9
  - ログ間のラグ：一定（正負）／行ごとのばらつき
  - ログBの打刻：ラグの大きさと乗る側
  - 同じ秒の中の行順の入れ替え，行そのものの欠落
  - ロボットの動作時間のばらつきと外乱
  - 低負荷だけの1か月と，低負荷・高負荷が混ざった1か月
- **指標**（目安．合意が必要）
  - g の誤差 ≤ 0.2 s，W の誤差 ≤ 2%，s の誤差 ≤ 1 s
  - ρ の誤差 ≤ 0.02，Δ の誤差 ≤ 1 s
  - カセットごとのボトルネックの一致率
  - T_line^min ÷ T_true（楽観の度合い）
  - 印の正しさ：区間に真値が入っているか，「未観測」の判定が妥当か
- **投入間隔への不変性**：投入間隔だけを変えても，同じ部位の推定値が動かないことを確かめる．
- **最重要試験**：限界より十分長い投入間隔の1か月ログだけから，A/B/C の限界とボトルネックをどこまで再現できるか．

## 生成器の修正が必要な点

ログCの待ちの記録方式を追加する項目は，START〜END に待ちが含まれないと確認できたので不要になった．現行の生成器は，この点で実機と同じ動きをしている．

0. 【必須】ログCの MOVE：実ログと同じく，MOVE の行を出さない設定にする．検証の答え合わせのため，真値には MOVE を残す．
1. 【必須】待機位置：置き先が処理中でも，次のマテリアルを持って処理層の前まで移動し，MOVE の END の後で待つ動作にする．現行は `dispatch.candidate_tasks` が作業を返さず，上流で待つ．比較のため，現行の動作も設定で選べるようにする．
2. 【必須】ログBとログCのラグ：設定で，一定の分と行ごとのばらつきを与えられるようにする．
3. 【必須】真値の拡充：truth_robot_ops に，待ちの理由と待ち先，対象のマテリアルを加える．新たに truth_capacity.json を出し，(Pos, 処理ID) ごとの c，段の C，ロボットの W と手順を，設定から解析的に計算して出力する．取り込みが待たされたかを，取り込みごとに出す．
4. ログの並び順の修正：writers.fmt は，打刻した秒の値と，記録に追加した順で並べている．基本は (秒, 実際の時刻) で並べ，検証用に，同じ秒の中の順序を乱すオプションと，START/END の行そのものを欠落させるオプションを追加する．
5. ログBの打刻の選択肢：OUT・IN を PICK/PLACE の開始と完了のどちらで打つか，ラグを下流の IN と上流の OUT のどちらに乗せるか．
6. 入力のスケジュールの拡張：カセットごとに投入間隔と処理IDを指定できるようにする（例：input.interval_schedule）．1か月の中に低負荷と高負荷を混ぜ，ボトルネックの移り変わりと κ の校正を検証するため．
7. ロボットの動作時間のばらつき（jitter）と外乱を与えられるようにする．処理の開始の遅れ（IN から処理開始まで）のオプションを追加する．
8. 検証専用の補助スクリプト：処理IDを固定して過負荷で走らせ，T_true^min(k) と真のボトルネックを求める．推定側からは使わない．

## ユーザー確認事項

### 回答済み

| 項目 | 回答 |
|---|---|
| Q1. 待ちはログCのどこに入るか | START〜END には入らない．END から次の START までが待ち |
| Q2. 動作の粒度と重なり | 取る・置く動作は別々の行で，それぞれ START と END がある．MOVE は記録されない．Upper と Lower の動作は基本的に重ならない |
| Q3. ログBとログCの時刻 | 通信のラグのため，完全には一致しない．ラグのばらつきは，試算で影響が小さいと分かったので質問を取り下げた．実データで幅を測り，大きければ警告する |
| Q4. 処理層の理論値と待機位置 | 取る・置く動作を含める．次のマテリアルを持って処理層の前まで移動し，移動の後で待つ |
| Q5. 余裕の基準 | ログAの取り込み間隔ではない．各 Pos にあと何秒早い間隔でマテリアルが来ても，その Pos が律速しないか，の意味 |
| Q6. 同じ段の並列層 | 同じ処理IDなら，処理時間は同じとみなしてよい |

### Q7. 移動の時間は，ログCのどこに入りますか

ロボットが別の場所へ移動してマテリアルを取る場合，PICK の START は，移動を始める時刻と，着いて取り始める時刻のどちらですか．

- なぜ重要か：提案は「着いて取り始める時刻」（移動は END から次の START の間にある）を前提にしている．移動を始める時刻なら，移動時間は START〜END に含まれ，END から次の START までがすべて待ちになるので，追跡が不要になる．
- 推奨：分からなければ，実ログで同じ場所の PICK の長さを見る．直前の位置によって長さが変わるなら，移動が含まれている．

### Q8. ロボットが何も持たずに処理層の完了を待っている時間は，余裕に数えますか

- なぜ重要か：例えば処理ID A の R1 は，86.37 s の間隔で 1枚あたり手空きが 26 s，処理待ちが 40 s である．手空きだけを数えると 26 s，処理待ちも数えると 66 s 詰められることになる．実際のライン全体の限界は 51.34 s（35 s 詰められる）で，R1 は律速していない．
- 推奨：主な値を手空き＋処理待ち＋保持待ちとし，手空きを確実な下限として併記する．入れ替えが起きれば，処理待ちの間に次のマテリアルを取りに行けるため．

### Q9. 下流から上流へ戻る移動時間は，上流→処理層 と 処理層→下流 の和より長くならないと見てよいですか

往復の移動時間が同じで，遠回りより遠くならない，という前提である．

- なぜ重要か：下流から上流へ戻る移動は，次のマテリアルを待つ時間と分けられない．余裕が大きいログでは，この前提が W_r の上界の根拠になる．
- 推奨：成り立つなら，そのまま上界として使う．成り立たない配置があれば，その移動時間を設定として与えられるようにする．

## 採用しなかった案

| 案 | 理由 |
|---|---|
| 余裕の基準をログAの取り込み間隔にする | 余裕は，各 Pos に来る間隔に対して，その Pos が律速しないかの意味である（ユーザー確認）．その Pos の入場間隔を基準にする． |
| MOVE の長さをログCの START〜END から直接測る | 実ログに MOVE は記録されない．動作の間隔から求める． |
| ログBの隣り合うイベントの間隔を区間とし，入れ替え手順に沿って足して W を求める（旧案の中心） | 投入間隔が長いと入れ替えが観測できず算出できない．区間の値も投入間隔に引きずられる（120 / 200 / 600 s で 27 / 107 / 507 s，真値 7 s）． |
| 連続する置き完了の間隔を，処理層の能力の主な値にする（旧案の c^eff） | 入れ替えの成立が前提で，余裕のある部位ほどサンプルが得られない．処理時間と動作の長さの和に置き換える． |
| ログCの END とログBの時刻の完全一致で動作を特定する | ログ間にラグがあり，一致しない．ラグを測り，順序を保って割り当てる． |
| ログ間のラグの中心を中央値で取る | 秒打刻では 0 か 1 に丸まり，MOVE と同点になる．行ごとに 0〜1 s のラグで，判定が 86% まで落ちた．平均なら 100%． |
| 値の無い部位を除いて max を取る | 限界を過小評価し，律速部位も誤る（86.4 s の C で 81.34 s，真値 83.99 s）．区間のまま max を取る． |
| 動作の長さの最小値を g とする | 秒の切り捨てと外乱に弱い．中心を使う． |
| ログCの稼働の割合を ρ とする | 現在の負荷での稼働であり，能力に対する負荷ではない．参考値としてだけ出す． |
| δ_resp(ρ) を a·ρ/(1−ρ) などの関数形で回帰し，不動点を解いて保守側の限界とする | 関数形を決め打ちし，低ρ側から外挿している．ログから計算しただけとは言えず，推測が入る． |
| 現在の負荷での待ちを能力に足す | 待ちは負荷によって変わるので，能力の値にはならない．待ちは内訳として別に出す． |
| 飽和したカセットで学習した補正係数 κ を，他の処理IDやボトルネックの種類にも当てはめる | 根拠の無い外挿．κ は同じ (処理ID, ボトルネック部位) にだけ適用する． |
| 指定の取り込み間隔を，カセット内の取り込み間隔の最頻値で推定し，入口詰まりの判定に使う | カセット全体が飽和していると，飽和した間隔そのものを指定値と誤認する．設定値が手に入る場合だけ使う． |
| ロボットの理論値を『観測されたサイクル型のうち最小のもの』とする | 高負荷では維持できない型を選ぶ恐れがある．確認済みの入れ替え手順から作った和を主な値とする． |
| ハンドへの MOVE の配分（Σc_h ＝ c_r）を，ハンドPos の能力として出す | 配分は約束事で，能力と誤読される．ハンドの能力はロボットの値を共有する． |
| 滞在時間分布の左端（下側の分位点）を，純粋な処理時間の点推定とする | 待ちの最小値が 0 にならない (Pos, k) で系統的にずれる．手空きサンプルで求める． |
| 待ち時間行列（KLM の拡張），状態分解（WORK/HANDLE/BLOCK/STARVE）を，ボトルネック判定の主な手段とする | 低負荷では矢印が投入側を指す．ボトルネックの予測は max C_i で行い，待ちの集計は診断にとどめる． |
| 全部位に共通の時刻窓，またはログAの取り込みを基準にした窓で，カセットごとの ρ を出す | 装置内に仕掛かりがたまる余地があるため，上流が先に進み，ρ>1 が出る．部位ごとにずらした窓と，マテリアルの帰属で集計する． |
| 処理IDの構成比で平均した c から max を取る | 楽観的に偏る（61 s に対し，実測は 63.1 s）．カセット（処理ID）ごとに max を取ってから，枚数で重み付けして平均する． |
